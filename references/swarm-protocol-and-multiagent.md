# Протокол взаимодействия роя агентов (Swarm Protocol)

## 1. Суть и назначение
**Swarm Protocol (Рой агентов)** - архитектурный стандарт децентрализованной мультиагентной разработки, при котором несколько независимых AI-агентов параллельно решают одну общую задачу в едином рабочем пространстве без жесткого центрального планировщика.

Главная цель: ускорение поставки кода (сокращение времени цикла примерно в два раза по сравнению с одиночным агентом), защита контекста от раздувания и исключение взаимных перезаписей файлов.

---

## 2. Ключевые принципы протокола

1. **Одна общая цель**: Задача передается рою агентов целиком. Агенты самостоятельно декомпозируют зоны ответственности и фиксируют границы на лету.
2. **Единый рабочий каталог**: Все агенты работают в одном репозитории и видят изменения файлов в реальном времени. Перезапись чужих файлов без согласования строго запрещена.
3. **Статус решений [DECISION]**: У каждого агента есть уникальный позывной (например, `@Agent_A`, `@Agent_B`). Любое ключевое архитектурное соглашение, интерфейс TypeScript или контракт API отправляется с префиксом `[DECISION]`. Все маркеры `[DECISION]` обязательны для безоговорочного исполнения каждым участником роя.
4. **Правило тишины (Zero Noise Communication)**: Категорически запрещены статусные и вежливые реплики без содержательной нагрузки ("принял", "согласен", "закончил", "понял"). Шум исключен. Агент либо отправляет конкретный факт / контракт / решение, либо молча выполняет код.
5. **Контекстная изоляция**: Каждый агент держит в фокусе только свой закрепленный модуль, предотвращая галлюцинации и перегрузку токенов.

---

## 3. Трехфазный исполнительный алгоритм

### Фаза 1: Координация (Правки кода строго запрещены)
На этом этапе ни один агент не имеет права создавать или изменять файлы в репозитории.

**Действия агента**:
1. Изучить репозиторий, архитектуру и поставленную задачу.
2. Отправить в общий канал структурированное предложение:
   - Закрепляемая за собой часть функционала (UI-компоненты, валидация, логика состояния, интеграция API или тесты).
   - Исчерпывающий список файлов, которые агент будет создавать или редактировать.
   - Предлагаемые типы, интерфейсы TypeScript и контракты взаимодействия.
3. При пересечении зон ответственности или файлов агенты оперативно согласовывают разделение и фиксируют его через `[DECISION]`.

### Фаза 2: Реализация (Хирургическая работа в своем контуре)
После фиксации зон ответственности агенты приступают к параллельному написанию кода.

**Действия агента**:
1. Писать код строго в пределах закрепленного списка файлов.
2. Не модифицировать файлы, за которые отвечают другие участники роя.
3. Следовать всем утвержденным `[DECISION]`.
4. При возникновении непредвиденной блокировки отправлять адресный запрос с конкретным вопросом или предлагать новое `[DECISION]`.

### Фаза 3: Синхронизация и догон
Этап сведения модулей в единое целое.

**Действия агента**:
1. Прочитать входящие сообщения и решения, поступившие во время написания кода.
2. При необходимости адаптировать свой код под обновленные контракты напарников.
3. Провести локальную проверку: сборка, линтер и тесты своего модуля.
4. Финализировать работу без лишних подтверждающих сообщений.

---

## 4. Формат коммуникации в рое

### Адресация
- Личное обращение: `@Agent_ID [сообщение]`
- Общее обращение: `@All [сообщение]`

### Фиксация контракта
```text
@All [DECISION] Интерфейс профиля пользователя:
export interface UserProfileData {
  id: string;
  username: string;
  isActive: boolean;
}
Файлы зоны ответственности @Agent_A: src/components/UserProfile.tsx, src/types/user.ts
```

### Запрещенные сообщения
- "Принял, приступаю к работе"
- "Согласен с решением"
- "Я все сделал, проверяйте"
- "Спасибо за помощь"

Если действие не требует изменения чужих контрактов или устранения конфликта, обмен сообщениями не производится.

---

## 5. Чек-лист роевой дисциплины
- [ ] Фаза 1 завершена: файлы распределены, конфликты устранены, контракты согласованы.
- [ ] Ни один файл вне закрепленной зоны ответственности не затронут.
- [ ] Все маркеры `[DECISION]` соблюдены в коде и типах.
- [ ] Нет мусорных сообщений в канале связи.
- [ ] Сборка и тесты проверены перед завершением сессии.
