# Библиотека Few-Shot калибровок («Слоп → Чистый текст»)

Языковые модели значительно лучше понимают конкретные пары примеров («как не надо» vs «как надо»), чем абстрактные запрещающие инструкции. Данная библиотека содержит эталонные пары калибровки для основных жанров.

---

## Пример 1: Техническая статья на Хабр

### ❌ Было (Нейрослоп):
> В современном мире разработка отказоустойчивых систем является не просто важной задачей, а настоящим стратегическим императивом для любого развивающегося бизнеса. Стоит отметить, что микросервисная архитектура открывает поистине безграничные горизонты, однако она требует комплексного подхода к мониторингу. Данный инструмент играет ключевую роль в обеспечении стабильности, позволяя командам выходить на качественно новый уровень надежности. Подводя итог, можно с уверенностью сказать, что правильный выбор стека определяет успех всего предприятия.

### Разбор дефектов:
* 4 жестких бана («В современном мире», «не просто X, а Y», «Стоит отметить», «играет ключевую роль»).
* 3 корпоративных штампа («стратегический императив», «безграничные горизонты», «качественно новый уровень»).
* Полный ноль фактов, цифр и конкретики.

### ✅ Стало (Чистый инженерный текст):
> Если микросервисы падают без внятного трейсинга, дежурный инженер тратит полночи на разбор логов в пяти подах. Мы развернули OpenTelemetry и связали спаны с метриками Prometheus. Время локализации сбоя сократилось с сорока минут до трех. Главное здесь — не собирать лишние события, иначе база метрик забьет диск за два дня.

### ✅ Стало (Твердая позиция):

## Пример 5: Кодовый слоп (ООП-догматизм) против Data-Oriented реальности

### ❌ Было (ООП-слоп и мнимая «чистота»):
```cpp
// Мнимая красота: 4 уровня абстракции, виртуальные вызовы, аллокации в куче
class ITransformable {
public:
    virtual void update(float dt) = 0;
    virtual ~ITransformable() = default;
};

class Entity : public ITransformable {
    std::shared_ptr<TransformComponent> m_transform;
public:
    void update(float dt) override {
        m_transform->integrateVelocity(dt);
    }
};

// В игровом цикле: промахи кэша, срыв SIMD-векторизации, аллокация на тик
for (const auto& entity : scene.getAllEntities()) {
    entity->update(dt);
}
```

### Разбор дефектов:
* Каждый объект лежит в произвольном месте кучи (Cache Misses).
* Виртуальный вызов на каждый шаг делает невозможным инлайнинг и векторизацию (SIMD).
* Убийство бюджета кадра (16.6 мс) на пустые координационные прыжки.

### ✅ Стало (Data-Oriented чистота):
```cpp
// Данные лежат непрерывным массивом в памяти (SoA), 0 аллокаций в цикле
struct PhysicsSystem {
    std::vector<Vec3> positions;
    std::vector<Vec3> velocities;

    void update(float dt) {
        const size_t count = positions.size();
        #pragma omp simd
        for (size_t i = 0; i < count; ++i) {
            positions[i] += velocities[i] * dt;
        }
    }
};
```
* Результат: код в 10 раз быстрее, процессорный кэш загружен непрерывно, компилятор применил AVX/SIMD инструкции.
