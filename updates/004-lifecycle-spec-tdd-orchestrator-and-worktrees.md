# Обновление 004: Жизненный цикл задачи, спецификация spec.md, TDD, оркестратор и Git Worktrees

## Статус
Принято и внедрено в ядро стандарта GO-FRONT. Обязательно к исполнению всеми агентами во всех сессиях.

---

## 1. Проблема
Ранее при длительной разработке, сжатии контекста или перезапуске сессий терялась нить задачи:
- Агенты начинали писать код без четкого понимания рамок и добавляли отсебятину.
- Терялся текущий прогресс: новый агент не знал, что уже сделано, что упало, а что осталось.
- Тесты писались постфактум или не писались вовсе.
- Несколько агентов мешали друг другу в одной рабочей директории.
- В интерфейсы просачивался визуальный мусор (glow, лишние кнопки, нелепые слоганы вроде "zero bloat").

---

## 2. Что внедрено в стандарт

### 2.1. Core Development Rules (Базовые правила разработки)
Зафиксированы в корневом `SKILL.md`:
1. **Только то, что попросили**: категорический запрет добавлять элементы, кнопки, декорации, glow, анимации или тексты без прямого запроса. Чужой код вне задачи не трогать.
2. **Никакого мусора (Anti-Slop)**: пустое пространство - естественная часть дизайна. Запрещено заполнять пустоту ради видимости.
3. **Названия по функционалу**: запрет абстрактных имен (`Helper`, `Manager`, `Utils`, `Handler`, `Stuff`). Имена должны раскрывать суть (`PaymentCalculator`, `UserProfile`).
4. **Чистая структура кода**: разделение по реальной ответственности, вынос повторной логики, запрет создания модулей "впрок".
5. **Фильтр перед созданием**: 5 проверочных вопросов перед добавлением любого элемента.
6. **Выходной контроль**: обязательная проверка diff перед сдачей.
* **Главный принцип**: Сначала понять задачу -> сделать ровно необходимое -> не добавлять ничего сверху -> проверить результат.

### 2.2. Живая спецификация (spec.md)
Для каждой существенной задачи в корне проекта создается и непрерывно ведется `spec.md` - единственный источник правды:
- 16 секций: Goal, User Requirements, Functional, UI/UX, Technical, Constraints, Architecture, Implementation Plan, Progress (`[x]`, In Progress, Remaining), Decisions, Work Log, Current State, Next Action, Verification, Tests (TDD), Final Result.
- `spec.md` обновляется на каждом шаге. Запрещено ставить `[x]`, пока функционал фактически не проверен.
- При смене требований агентом фиксируется запись в `Decisions`.

### 2.3. Оперативная память сессии (memory_front.md)
Легкий снимок текущей рабочей сессии:
- Фиксирует: текущую задачу, что сделано, что делается прямо сейчас, последнее изменение, проблемы, следующий шаг и затронутые файлы.
- Позволяет мгновенно восстановить контекст при сжатии истории или старте новой сессии (`/new`) через цепочку: `SKILL.md -> spec.md -> memory_front.md`.

### 2.4. TDD (тесты до реализации)
- Поведение описывается тестом ДО написания кода.
- Рабочий цикл: `Поведение -> Тест -> RED -> Минимальный код -> GREEN -> Проверка граничных случаев -> Повторный запуск`.
- Фиксация статуса `RED / GREEN` и лога верификации в `spec.md`.

### 2.5. Оркестратор и жесткие границы задач
- Оркестратор декомпозирует задачу, передает дочерним агентам строгий контракт (`Task, Goal, Requirements, Constraints, Scope, Verification`).
- Запрет мультиагентности ради самой мультиагентности.
- Дочернему агенту категорически запрещено расширять scope; смежные проблемы эскалируются оркестратору.
- Дочерний агент возвращает развернутый отчет с измененными файлами и результатами тестов вместо сухого "Done".

### 2.6. Изоляция через Git Worktrees
- Независимые задачи выполняются в изолированных директориях и ветках (`worktree-auth`, `worktree-ui`).
- Никаких прямых коммитов в основную ветку из worktree.
- Обязательный аудит перед Merge: сверка со `spec.md`, отсутствие лишнего кода, прохождение сборки и тестов.

### 2.7. Визуальная гигиена и ресурсы
- В `cognitive-ergonomics-and-minimalism.md` закреплен Раздел 6: запрет скачков анимаций при скролле (только opacity 0->1), чистый центр, зазоры 32-40px+, угловая фиксация ярлыков, запрет слоганов в UI.
- В `verified-ui-ux-resources.md` интегрирован пак **Eva Icons** (8.8k звезд, Outline/Fill, анимации).

## 3. На что обращать внимание агентам

1. **Воспроизводимость без истории чата**: Любой новый агент должен получить `SKILL.md`, `spec.md` и `memory_front.md` и сразу понять, что делать, без чтения сотен сообщений диалога.
2. **Не придумывать отсебятины**: Реализовывать ровно то, что запрошено.
3. **TDD-дисциплина**: Если логику можно протестировать - тест пишется до кода.
4. **Всегда проверять `Current State` и `Next Action`** перед началом работы.
